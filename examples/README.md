# 示例（examples）

本目录存放**可直接运行**的示例，用于演示插件的实际行为，也是理解反虚构铁律最快的方式。

```bash
node examples/rewrite-demo.mjs
```

## 文件说明

| 文件 | 说明 |
|---|---|
| `rewrite-demo.mjs` | 用一组真实风格的 JD + 简历，演示工具返回值与三段式交付结构 |
| `fixtures/frontend-jd.txt` | 示例岗位描述（前端开发） |
| `fixtures/frontend-resume.txt` | 示例简历（与 JD 存在明显能力缺口，用于演示「待补充清单」） |

## 这个示例想说明什么

示例中的简历刻意选择了一个**能力缺口明显**的场景（JD 要求 Vue3/TypeScript/Vite/Nuxt，
简历只有 Vue2）：

- 正确的行为：这些缺口能力**不被编造**，而是进入「待补充清单」
- 错误的（本插件杜绝的）行为：把 Vue2 包装成 Vue3、凭空加上 TypeScript 经验

若你想验证铁律是否真的生效，可以修改 fixtures 里的简历，加入更多与 JD 不匹配的内容，
观察工具的返回值是否仍然拒绝编造。

## 为什么示例跑的是 core.js 而不是完整插件

完整插件的加载需要 DSH 宿主运行时（见主 README 的「快速开始」一节）。
但本插件的**全部业务逻辑**都在零依赖的 `src/core.js` 中，
所以示例可以在任何装有 Node 20+ 的机器上直接运行，无需 DSH。

这也是本项目分层设计的直接收益：核心逻辑可独立验证。
